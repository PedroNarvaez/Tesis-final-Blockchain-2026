## 2026-07-20 - Accessible and Clickable Configuration Inputs and Checkboxes
**Learning:** In complex enterprise dashboards, sidebar controls and filters often suffer from poor accessibility (missing htmlFor/id associations) and tiny click targets for checkbox/toggle inputs. Associating labels properly and making entire row blocks clickable with subtle hover highlights greatly enhances interaction convenience, especially on smaller screens or for keyboard-only/screen-reader users.
**Action:** Always link form labels to their inputs using htmlFor and unique IDs. For checkboxes or toggles, wrap the descriptions in label tags and make the container interactive/clickable so that clicking any descriptive text toggles the target checkbox directly.

## 2026-08-09 - Keyboard Navigability and Semantics for Custom List Selection Items
**Learning:** Dense enterprise dashboards that render stream logs, custom tables, or list items (like Exceptions list items or Blockchain Blocks list items) often use non-semantic elements like `div` or `li` with click handlers for selecting details. This prevents screen reader identification and blocks keyboard focus/navigation. Using semantic `<button type="button">` wrappers with explicit `aria-label` attributes and focus ring indicators allows keyboard-only or screen-reader users to seamlessly tab and navigate the dashboard.
**Action:** Always wrap interactive selection elements in a list/grid with semantic `<button type="button">` and configure visible focus styling (`focus-visible:ring-2`) and descriptive `aria-label` fields.
