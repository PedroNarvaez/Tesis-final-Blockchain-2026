## 2026-07-20 - Accessible and Clickable Configuration Inputs and Checkboxes
**Learning:** In complex enterprise dashboards, sidebar controls and filters often suffer from poor accessibility (missing htmlFor/id associations) and tiny click targets for checkbox/toggle inputs. Associating labels properly and making entire row blocks clickable with subtle hover highlights greatly enhances interaction convenience, especially on smaller screens or for keyboard-only/screen-reader users.
**Action:** Always link form labels to their inputs using htmlFor and unique IDs. For checkboxes or toggles, wrap the descriptions in label tags and make the container interactive/clickable so that clicking any descriptive text toggles the target checkbox directly.

## 2026-07-21 - Accessible Semantic Buttons for Worklists and Option Streams
**Learning:** In list-based master-detail dashboard layouts, using passive containers like `div` or generic anchor tags for interactive rows hinders screen readers and keyboard navigation. Using a semantic `<button type="button">` with focus indicators (`focus-visible:ring-2`), clear ARIA selections (`aria-selected`), and highly descriptive `aria-label` screen reader explanations provides a superb, standards-compliant navigation experience.
**Action:** Always wrap list-based master-detail selection rows in semantic `<button type="button">` tags. Provide a robust, voice-synthesizer friendly `aria-label` detailing the list item's code, primary title, priority/status, and exposure, and ensure interactive focus visible outline borders are clearly visible when navigating with a keyboard.
